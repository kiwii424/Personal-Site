Retrieval-Augmented QA

Research-Paper QA — RAG Pipeline 與部署服務Research-Paper QA — RAG Pipeline & Deployed Service

輸入一篇 NLP 論文全文和一個問題，系統回傳簡短答案，加上支撐答案的原文證據片段。送去評分的證據就是 LLM 實際看到的 context，背後不多塞任何東西。Given a paper's full text and a question, the system returns a short answer plus the exact evidence spans that support it. The evidence submitted for scoring is exactly the context the model saw — nothing extra behind the scenes.

01這個專案在做什麼What this project does

任務是論文問答：hidden test set 有 100 篇 NLP 論文、每篇一個問題，系統要給出答案和證據片段。評分有兩項——答案正確性由 LLM judge 判對錯；證據分數是各片段的 ROUGE-L 除以送出的片段數，多塞片段會直接扣分。這個專案從研究腳本一路做到可部署的服務：pipeline/ 在 benchmark 上衝分，service/ 把同一套想法包成有測試、容器化、可以對任意貼上論文問答的 API。The task is paper QA: a hidden test set of 100 NLP papers, one question each; the system must return an answer and evidence spans. Scoring is two-fold — answer correctness from a binary LLM judge, and an evidence score of per-span ROUGE-L divided by the number of submitted spans, so padding actively hurts. The project goes from research script to deployable service: pipeline/ maximizes benchmark scores, service/ repackages the idea as a tested, containerized API that answers questions over any pasted paper.

03怎麼做How it works

1Parent–child chunkingDocumentProcessor
依句子切 chunk，尺寸從資料量出來：golden evidence 中位數 216 字元，所以 child chunk 目標 200 字元（上限 350、重疊 2 句），每個 child 保留約 1,200 字元的 parent window 給 reranker 和 LLM 當上下文。Sentence-based chunking sized from the data: golden evidence spans have a median of 216 characters, so child chunks target 200 chars (max 350, 2-sentence overlap), each keeping a ~1,200-char parent window for the reranker and the LLM.
2Hybrid retrievalFAISS + BM25 + HyDE
FAISS 稠密檢索（snowflake-arctic-embed-l-v2.0）加 BM25，配 query 變體與 HyDE，用 Reciprocal Rank Fusion（k=60）融合。FAISS dense search (snowflake-arctic-embed-l-v2.0) plus BM25, with query variants and HyDE, fused by Reciprocal Rank Fusion (k=60).
3Cross-encoder rerankbge-reranker-v2-m3
Cross-encoder 重排序，加 section boosting（query routing 命中的章節 +1.5）。Ablation 掃過 embedder × reranker 組合後，arctic-embed + v2-m3 這對最好。Cross-encoder reranking with section boosting (+1.5 for sections matched by query routing). An ablation sweep over embedder × reranker pairs picked arctic-embed + v2-m3.
4Dynamic K1/K
證據分數除以 K（送出的片段數），所以只留 rerank 分數為正的 chunk，分差大於 2.0 就截斷。實驗下來 K ≥ 2 是底線：單一片段很少夠 3B 模型可靠作答。The evidence metric divides by K (submitted span count), so only positively-scored chunks are kept, cut at a score gap of 2.0. Experiments showed K ≥ 2 is the floor: one span rarely carries enough context for a 3B model.
5Sentence-level refinementevidence = context
生成前把 top chunk 拆成單句與滑動視窗重新打分，選出最小、最精準的不重疊片段——這些片段同時是送去評分的證據和 LLM 的 context，一致性由構造保證。Before generation, single sentences and sliding windows from the top chunks are re-scored; the best non-overlapping spans become both the submitted evidence and the LLM context, so the faithfulness constraint holds by construction.
6Type-aware generationLlama-3.2-3B
先分類問題型別（number / list / yesno / reason / method / factoid），套對應 prompt、temperature 0；「I don't know」自動重試，最後把答案 snap 回逐字的證據原文。The question is classified (number / list / yesno / reason / method / factoid) and prompted accordingly at temperature 0, with IDK-recovery retries; the answer is snapped back to verbatim evidence text.
留下來的負面結果Negative results, kept on purpose

「長片段加分」：假設長片段與 golden evidence 重疊更多，結果兩項指標都變差（0.249 / 50）。Cross-encoder 本來就校準得好，加分只是把平庸的長片段推上去。A length bonus (hypothesis: longer spans overlap golden evidence more) made both metrics worse (0.249 / 50) — the cross-encoder is already well calibrated, and the bonus just promoted mediocre long spans.

「Adaptive K 從 1 開始」：public split 上證據分 +0.044，但 hidden set 正確性掉 9 篇——弱答案偵測器放過太多看似合理其實錯誤的 K=1 答案。Adaptive K starting at 1 gained +0.044 evidence on the public split but lost 9 papers of correctness on the hidden set — the weak-answer detector passed too many plausible-but-wrong K=1 answers.
