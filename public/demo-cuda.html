01這個專案在做什麼What this project does

課程期末專案：用 CUDA 實作並優化修改版 LeNet-5 兩層卷積（C1、C3）的前向傳播，模型對 Fashion-MNIST 做推論——一批 10,000 張 86×86 灰階影像，輸出 10 類。評分看兩層卷積的 op time 總和：≤ 60ms 拿滿分、> 100ms 零分。卷積是 CNN 最貴的運算，這個專案就是把它在 GPU 上一路壓快的完整過程，分三個 milestone 進行。The course final project: implement and optimize the forward pass of two convolution layers (C1, C3) in a modified LeNet-5 with CUDA, running inference on Fashion-MNIST — a batch of 10,000 grayscale 86×86 images, 10 output classes. Grading measures the total op time of the two layers: ≤ 60ms is full credit, > 100ms is zero. Convolution is the most expensive op in a CNN; this project is the full journey of making it fast on a GPU, across three milestones.

有趣的是中間那步：把卷積展開成矩陣乘（im2col）後反而變慢——unroll 本身要寫一份巨大的中間矩陣（Channel·K² × Batch·H·W，大到索引會爆 INT_MAX）。它的價值在下一步才兌現：矩陣乘的形式讓 tiling、Tensor Cores、cuBLAS 這些武器都能上場。The interesting step is the middle one: unrolling convolution into a matrix multiply (im2col) is initially slower — the unroll writes a huge intermediate matrix (Channel·K² × Batch·H·W, big enough to overflow INT_MAX indexing). Its value pays off next: the GEMM form is what lets tiling, Tensor Cores, and cuBLAS come into play.

03每一步在做什麼What each step does

1直接卷積 kernelDirect convolution kernelnew-forward.cu
每個 thread 算一個輸出像素：對 input 的 K×K 視窗與濾波器做內積。host 端分三段——prolog 配置記憶體並搬資料上 GPU、conv_forward_gpu 設定 grid/block 並發射 kernel、epilog 搬結果回來。正確性先於速度：batch 10,000 準確率 0.8714。One thread per output pixel: a dot product between a K×K input window and the filter. Host code has three phases — prolog allocates and copies to the GPU, conv_forward_gpu configures the grid and launches, epilog copies back. Correctness first: 0.8714 accuracy at batch 10,000.
2im2col unrollingunroll-new-forward.cu
把每個 K×K 輸入視窗攤平成一欄，卷積就變成「濾波器矩陣 × 展開矩陣」的 GEMM，再把結果 permute 回 Batch × Map × H × W。三個 kernel：unroll、matmul、permute。展開矩陣超過 INT_MAX，索引全部用 size_t。Each K×K input window is flattened into a column, turning convolution into a GEMM of filter matrix × unrolled matrix, with a final permute back to Batch × Map × H × W. Three kernels: unroll, matmul, permute. The unrolled matrix exceeds INT_MAX, so all indexing uses size_t.
3Kernel fusionkernel-fusion-forward.cu
把 unroll、tiled matmul、permute 融成一個 kernel：載入 shared memory tile 時直接從原始 input feature 取值（隱式 unroll），寫回時直接放到 permute 後的正確位置。整份巨大中間矩陣從此不用寫進 global memory，~200ms 掉到 ~60ms。Unroll, tiled matmul, and permute fused into one kernel: shared-memory tiles load straight from the original input features (implicit unroll), and outputs are written directly to their permuted positions. The huge intermediate matrix never touches global memory — ~200ms drops to ~60ms.
4Streamsrequired · m3
把 batch 切段，用多條 CUDA stream 讓「上傳資料、跑 kernel、下載結果」互相重疊；host 記憶體要用 pinned memory 才能非同步傳輸。最終效能提交依課程規定用單一 stream（多 stream 下 op time 不可靠）。The batch is split across CUDA streams so upload, kernel execution, and download overlap; host memory must be pinned for async transfers. The final performance submission uses a single stream per course rules (op times are unreliable under multi-stream).
5Tensor Cores (WMMA)required · m3
用 warp matrix functions 直接驅動 Tensor Core 做 16×16 tile 的矩陣乘，TF32 格式（精度不掉、準確率不變）。不透過 cuBLAS，自己排 fragment 的 load / mma / store。Warp matrix functions drive the Tensor Cores directly on 16×16 tiles in TF32 (no accuracy loss). No cuBLAS — fragment load / mma / store orchestrated by hand.
6其他個別實驗Other individual experimentsm3
constant memory 放濾波器權重、__restrict__ 解指標別名、loop unrolling、block size 與 thread coarsening 參數掃描、cuBLAS 對照、FP16/__half2（精度換頻寬，最終提交不用以保準確率）、register/shared memory tiling。每項個別實作、用 nsys/ncu 分析，最後只把加總最快的組合放進 m3-forward.cu。Constant-memory filter weights, __restrict__ for pointer aliasing, loop unrolling, block-size and thread-coarsening sweeps, a cuBLAS comparison, FP16/__half2 (precision for bandwidth — excluded from the final submission to keep exact accuracy), and register/shared-memory tiling. Each implemented individually and profiled with nsys/ncu; only the fastest end-to-end mix went into m3-forward.cu.
